# Local comparison benchmark authority

Contract version 4 distinguishes exploratory measurements from auditable authoritative rankings. A run records its fresh-process run ID, deterministic seed, run index, measured implementation order, measured scenario order, warmup count, measured count, raw timing samples, process identity, and a canonical artifact SHA-256. Result files are timestamped or explicitly run-scoped and must never overwrite an earlier run.

An authoritative aggregate requires complete seven-run position cycles from the same clean commit, working tree, runtime, host, browser, dependency set, build mode, and workload. Every implementation occupies every position exactly once per cycle. The validator regenerates implementation and scenario orders from the recorded seed and run index; altered, partial, or trailing incomplete cycles are rejected. The nine-scenario schedule also constrains early/late placement and mean position. Stable measurements use at least 5 warmups and 30 measured samples per implementation and scenario.

Raw `values` arrays are the authority source of truth. The validator recomputes the configured trimmed mean and rejects a contradictory stored summary. Each fresh process contributes one raw-derived candidate-to-fastest-competitor ratio per scenario; samples within that process are not treated as independent observations. The aggregate applies a deterministic run-level bootstrap and reports the median ratio and one-sided 95% upper bound. An upper bound below `1.00` is a reproducible win, and an upper bound at or below `0.99` is a meaningful win of at least 1%. Invalid manifests, duplicate process identities, dirty or incompatible provenance, undersampling, incomplete cycles, or uncertainty prevent an authoritative result.

Contract-v3 and older artifacts remain readable as historical measurements, but they cannot be promoted to authoritative rankings under the version-4 validator.
